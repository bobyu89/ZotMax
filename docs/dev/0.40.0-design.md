# ZotMax 0.40.0 design: D 檢索日誌、E 檢索健康檢查、F 檢索式體檢

Architect's design for the four implementation agents. Read this whole file before starting. The product spec is
`spec-040.md` (same folder); where the spec's proposals and its reviewer notes disagree, the reviewer notes won, and
this design already applies them. Where this design and the spec disagree, follow this design.

Ground rules (repeated from the task): UMD module pattern, tabs, the surrounding comment density and helpers; UI
strings in Traditional Chinese (Taiwan), terms like PubMed, MeSH, PRISMA kept in English. No AI anywhere in this
release. ZotMax arranges the user's own data, states facts and asks questions: it never changes a count the user owns,
never says the search is complete or sufficient, never rewrites the user's query, and every feature has an on/off pref.
Never edit package.json, manifest.json, updates.json, dist/, README.md, DESIGN.md or test/e2e/** (except the harness
file where this design names its owner). Never commit, push, build or use git stash.

Words that must never appear in any 0.40.0 UI string: 「查完了」「已完整」「足夠」「合格」「不及格」「分數」, and no
red/green traffic-light wording (「紅燈」「綠燈」). Tests for E and F assert their absence.

## 0. Decisions in one page

| Question | Decision |
|---|---|
| Where the search log lives | One JSON file per research project (Zotero collection, or the whole library) in the Zotero data directory: `<Zotero.DataDirectory.dir>/zotero-bridge/search-log/<scope file>.json`. This is the working copy and works without Obsidian. |
| Obsidian | When a vault is set, every write also renders the log note `<reviews folder>/檢索日誌/<collection name>.md` (organized: `<F>/30 評讀與綜整/檢索日誌/`, flat: `<F>/Reviews/檢索日誌/`). The note's managed block ends with a hidden copy of the data (`%% zotmax-search-log-data … %%`). On every read, the JSON and the note's copy are merged by entry id (newer `updatedAt` wins, deletions are tombstones), so a second computer that shares the vault gets the log, and a lost data directory is restored from the vault. |
| Why a subfolder | dashboard.js `projectRecords()` and progress-report.js `projectNotes()` list only the direct `.md` children of the reviews folder, so the log notes never show up as 「回顧專案」. vault-layout.js moves the whole `Reviews` folder (FOLDER_MOVES), so the subfolder follows a flat → organized migration with no change to vault-layout.js. |
| prefs | No log data in prefs. Only the switch, two sub-options and a short list (≤ 20) of pending 「補記一筆」 batches (`searchLog.pending`). |
| Switch | New feature switch `searchLog` (features.js, group 找文獻, pref `feature.searchLog`, guided **on**, advanced on, `since: 9`, no network, no AI). Sub-prefs `searchLog.offerAfterOpen` (default true) and `searchLog.autoDrafts` (default true). |
| PRISMA identified | Never replaced. The PRISMA note gets a 「檢索紀錄對帳」 section (日誌命中／日誌匯入／Zotero 標籤 per database) and a `logMismatch` issue that only points out the gap. `computePrisma()`'s counts and its `identified = duplicates + screened` check are untouched. |
| Stop reason | Frontmatter key `search_stop_reason` of the PRISMA note, written by the user. `buildReviewNote()` already keeps every frontmatter key it does not manage; E adds a placeholder (`search_stop_reason: ""`) only when the key is missing, and never writes a value. The health card and the progress report read it. |
| E switch | Pref `screening.healthCheck` (default true), inside the 篩選 feature. |
| F switch | Pref `queryCheck.enabled` (default true), applies to 測試檢索式 in PubMed 追蹤 and 主題搜尋機器人. The web page box (site/search.html) has no pref: it only runs when the user pastes a query and presses the button. |
| F scope | Only queries the user wrote or edited. A query is ZotMax-generated when it equals (whitespace-normalized) the string ZotMax put there: the PICO card query in the topic bot's setup, or the MeSH query a watch was saved with from 醫學文獻快速搜尋 (stored on the watch as `generated`). Everything else counts as the user's. |
| Shared files | Every shared file (prefs.js, preferences.xhtml/js, commands.js, features.js, bootstrap.js, main.js, locale/*, test/e2e/harness/bootstrap.js) is edited by **D in stage 1 only**, including the lines E and F need (spelled out in §5). Stage-2 parts touch no shared file. |

What these show, and what F must explain: PubMed silently ignores an unknown field tag (`[xyz]`, `fieldsnotfound`
stays empty); drops the `*` when the root is shorter than 4 letters (`fal*` → `"fal"`); ignores `~N` proximity on a
single word; accepts a wildcard inside a quoted phrase, with or without a field tag; processes Boolean operators left to
right; drops an unmatched `(` and reports it only as the output message `"("`; drops the words of a quoted phrase it
can't find and keeps the rest (`"zzqqx foo"` → `"foo"`); ignores lowercase `and` as a common word (implicit AND anyway).

## 2. D — 檢索日誌、PRISMA-S 草稿與對帳 (stage 1)

### 2.1 New module `content/search-log.js`

UMD like screening.js: `module.exports = factory(require("./core.js"), globalThis)` in Node, `root.ZB.searchLog` in
Zotero. Pure helpers first (Node tests), then the Zotero part. Header comment in the house style: what it is, the
storage, the entry points, the prefs.

#### Entry (the data model)

```js
{
	id: "l" + Date.now().toString(36) + rand,  // newEntryID(now)
	kind: "search" | "dedupe",
	status: "formal" | "exploratory",          // 正式／探索; only formal goes into PRISMA and PRISMA-S
	method: "database" | "register" | "website" | "citation" | "contact" | "other",   // PRISMA-S category
	database: "PubMed",                        // as the user names it (華藝線上圖書館, CINAHL, Google Scholar…)
	sourceTag: "PubMed",                       // the 來源/<X> value its records carry; defaults to database
	platform: "PubMed（NCBI）",                 // interface / platform / vendor (EBSCOhost, Ovid, 華藝…)
	query: "…",                                // the full query as run in that database (the user's text)
	sentQuery: "…",                            // PubMed only: what ZotMax actually sent (watchTerm adds the date filter)
	translation: "…",                          // PubMed only: querytranslation
	date: "YYYY-MM-DD",                        // date searched (local date)
	limits: "2015–2025；英文、中文",             // free text
	limitsReason: "…",                         // free text; empty = 待填 in PRISMA-S
	hits: 0 | n | null,                        // 0 is a real value; null = not filled
	importFile: "pubmed-falls-set.nbib",
	imported: n | null,
	notes: "",
	origin: "manual" | "pubmed-test" | "bot-test" | "link" | "import" | "pubmed-watch" | "topic-bot" | "dedupe",
	createdAt: ISO, updatedAt: ISO,
	deleted: true,                             // tombstone (kept so merging never brings an entry back)
	// kind "dedupe" only:
	rule: "DOI、PMID、標題＋年份、期刊＋年＋卷＋起始頁", records: n, groups: n, marked: n, alreadyMarked: n, cancelled: bool,
}
```

`normalizeEntry(raw)` coerces every field (strings trimmed, `hits`/`imported`/counts to integer ≥ 0 or null,
unknown enum values to their default: status "formal", method "database", kind "search", origin "manual"), fills
`sourceTag` from `database`, and never throws.

#### Pure functions (all exported)

- `newEntryID(now)`; `activeEntries(list)` (no tombstones); `formalEntries(list)` (active, kind search, formal).
- `mergeEntries(a, b)` → union by id, the newer `updatedAt` wins, a tombstone wins over an older live copy; sorted by
  `date`, then `createdAt`.
- `upsertAutoDraft(list, draft, { keep = 10 })` → list. An auto draft (origin `pubmed-watch` / `topic-bot`, always
  exploratory) replaces the draft with the same origin, `query` and `date` (one per day per query); then, per
  (origin, query), only the newest `keep` drafts that were never edited by the user (`updatedAt === createdAt`) and
  never promoted stay. Never touches manual or promoted entries.
- `dedupeEntry(info, now)` → a kind "dedupe" entry; `status: "formal"`.
- `SOURCE_ALIASES` and `sameSource(a, b)`: case- and width-insensitive (NFKC) match of database names or tag values,
  with aliases: PubMed = MEDLINE; 華藝 = 華藝線上圖書館 = Airiti Library = airiti; 臺灣博碩士論文 = 臺灣博碩士論文知識加值系統 =
  博碩士論文 = NDLTD; 國圖期刊 = 國家圖書館期刊文獻資訊網 = 臺灣期刊論文索引; Cochrane = Cochrane Library = CENTRAL;
  Google Scholar = Scholar = 谷歌學術; CINAHL = CINAHL Plus. (`台`/`臺` treated as the same.)
- `databasesSearched(entries)` → `[{ name, tag, method, hits, imported, dates: [] , entries: n }]` over formal search
  entries, grouped with `sameSource`; **includes 0-hit entries**. E uses this.
- `reconcile(entries, prisma, cfg)` → `{ rows, issue }`:
  - `prisma` is `computePrisma()`'s result; `tagged` for a database = the count of that source in `prisma.sources`
    plus `prisma.other.sources` (matched with `sameSource`); the `未標示來源` bucket is never matched.
  - one row per database that has formal entries or a tag: `{ name, tag, logHits, logImported, tagged, state, note }`,
    `state`: `"ok"` (imported or hits equal tagged), `"diff"`, `"noLog"` (tag without a formal entry; informational),
    `"noTag"` (formal entry with hits > 0, nothing tagged).
  - `logImported` is the sum of the entries' `imported` (null when none filled); `logHits` the sum of `hits`.
  - `"diff"` when `logImported !== null && logImported !== tagged`, or when `logImported === null && logHits !== null
    && logHits < tagged` (more tagged than the database returned: often a batch imported twice). Hits greater than
    tagged with no `imported` filled is **not** a diff (people export part of a result); the row says so in `note`.
  - `issue` is null, or `{ code: "logMismatch", level: "warn", message, records: [] }` when any row is `"diff"` or
    `"noTag"`. Message, one clause per row, e.g. 「華藝線上圖書館：日誌記匯入 42 筆，Zotero 有 30 筆標了 來源/華藝」,
    then the fixed tail 「可能原因：沒有全部匯出、匯入時沒加來源標籤、同一批匯入兩次，或已在 Zotero 合併或刪除重複。PRISMA 的辨識數仍用
    Zotero 標籤計數；要報哪個數字由你決定。」
  - Exploratory and deleted entries are ignored.
- `reconcileSection(rec, { link, layout })` → Markdown. Plain: `## 檢索紀錄對帳` + a short lead (「並列檢索日誌和
  Zotero 的數字；ZotMax 不會改 PRISMA 的辨識數。」) + table `| 資料庫 | 日誌命中 | 日誌匯入 | Zotero 標籤 | 說明 |` + 「檢索日誌：
  [[<link>|<name> 檢索日誌]]」. Board: `core.chartCard("檢索紀錄對帳", lines, true)` with one line per database
  (「PubMed · 命中 120 · 匯入 118 · 標籤 118 ✓」), the same link as the last line. Empty cells show 「—」.
- `noLogLine(link)` → 「還沒有檢索日誌：ZotMax → 檢索日誌（目前分類）… 記下每個資料庫的檢索式、日期和筆數（PRISMA-S）。」
- `PRISMA_S_ITEMS` (16, in order: 1 Database name 資料庫名稱, 2 Multi-database searching 同一平台一次查多個資料庫,
  3 Study registries 試驗登錄, 4 Online resources and browsing 網站與瀏覽, 5 Citation searching 引文追蹤, 6 Contacts
  聯絡作者或專家, 7 Other methods 其他方法, 8 Full search strategies 完整檢索式, 9 Limits and restrictions 限制條件與理由,
  10 Search filters 檢索篩選器, 11 Prior work 沿用的既有檢索式, 12 Updates 更新檢索, 13 Dates of searches 檢索日期,
  14 Peer review 檢索式同儕審查（PRESS）, 15 Total records 各資料庫筆數, 16 Deduplication 去重方法).
- `prismaS(entries, meta)` → `{ items: [{ n, en, zh, text, todo }], markdown, csv }`. Fill only what the log knows;
  everything else is the text 「待填」 plus a one-line hint of what to write. Rules:
  1 formal `database` entries: 「名稱（平台）」 list; 2 待填 (hint: 例如 EBSCOhost 一次查 CINAHL 和 MEDLINE); 3 `register`
  entries, else 待填; 4 `website` entries, else 待填; 5 `citation` entries, else 待填; 6 `contact`, else 待填; 7 `other`,
  else 待填; 8 every formal search entry's full `query` in a fenced block, grouped by database (with platform and date);
  9 per entry `limits` + `limitsReason`, an entry with limits but no reason gets 「理由：待填」, no limits anywhere →
  「沒有記錄限制條件」; 10 待填; 11 待填; 12 databases with formal entries on two or more dates: 「<db>：<date>、<date>」,
  else 待填; 13 per database the dates; 14 待填 (hint: 請館員或指導教授用 PRESS 檢核表看過檢索式); 15 per database `hits`
  (「待填」 where null) and the total, marked 「去重前」; 16 the newest dedupe entry 「<date> 用 ZotMax 找重複（<rule>）：<groups>
  組、標記 <marked> 筆」 + 「合併或刪除的方式：待填」, else 待填. `todo` is true for every item that has a 待填.
  Markdown: title 「PRISMA-S 檢索報告草稿（<name>）」, the lead 「這是草稿：只填了檢索日誌知道的事，其他標「待填」。正式附錄請自己核對。」,
  then the 16 items as a checklist `- [ ] 1. 資料庫名稱（Database name）：…` (checked `[x]` when not todo). CSV columns:
  項目, PRISMA-S, 內容, 狀態 (已填／待填), UTF-8 with BOM like screening.buildCSV.
- `logCSV(entries)` → CSV of active entries: 狀態, 方法, 資料庫, 平台, 日期, 檢索式, 限制條件, 限制理由, 命中, 匯入檔名, 匯入筆數, 備註, 來源.
- `buildLogSection(entries, meta)` and `buildLogNote(existing, entries, meta)`: frontmatter `title`, `type:
  "search-log"`, `zotero_collection` (scope key), `collection_path`, `zotero` (select URI), `log_formal`,
  `log_exploratory`, `last_generated` — **never any `prisma_*` key**. Managed block (core.MARK_START/END; plain or board
  per `core.layoutPref()`): metaFold (「由 ZotMax 依你的檢索日誌產生；要修改請在 Zotero：ZotMax → 檢索日誌（目前分類）…，重新產生只會覆寫這個區塊。」),
  正式檢索 grouped by database (each entry: date · platform · hits/imported, then the query in a fenced block, limits and
  reason, file, notes), 探索 (folded with core.foldBlock), 去重紀錄 (folded table), the PRISMA-S draft (folded), and last
  the data block. The 「✍️ 我的筆記」 part below the block is kept (same rules as screening.buildReviewNote).
- `encodeData(obj)` / `decodeData(text)`: data block
  ```
  %% zotmax-search-log-data
  {"v":1,"scope":"…","entries":[…]}
  %%
  ```
  JSON on one line with every `%` written as `%` (so `%%` can never appear inside). `decodeData` returns null for
  a note without a valid block and never throws.
- `scopeFileName(scopeKey)` → `scopeKey.replace(/[^\w.-]/g, "_") + ".json"`.
- `logFolderParts(settings)` → `[...core.vaultFolder(settings, "reviews"), "檢索日誌"]`.
- `shouldOfferLog(source)` → true for `lang === "zh"`, every source without a search URL (copy-only), custom sources,
  and the ids in `OFFER_IDS = ["cinahl", "cochrane", "embase", "jbi", "scholar", "trip", "clinicaltrials", "ictrp",
  "guideline-pdf", "tw-gov", "nice", "rnao", "gin", "cdc"]` (databases ZotMax can't count, and grey literature).
  False for pubmed, pubmed-cq, pubmed-sr (they have 測試檢索式), mesh, europepmc, semantic, uptodate, related.
- Prefills (pure; each returns a normalized draft entry, `status` given below):
  - `prefillFromTest(detail, { origin, now })` (origin `"pubmed-test"` or `"bot-test"`): database PubMed, sourceTag
    PubMed, platform 「PubMed（NCBI）」, method database, `query: detail.query`, `sentQuery: detail.sent`,
    `translation: detail.translation`, `hits: detail.count`, `date` today, `limits`: 「出版日期 <since> 起」 when
    `detail.since`, status formal.
  - `prefillFromTarget(target, now)`: database `target.name`, sourceTag = the alias-normalized name, method `website`
    for the grey-literature ids (guideline-pdf, tw-gov, nice, rnao, gin, cdc, trip), `register` for clinicaltrials and
    ictrp, else database; `query: target.query`; date today; hits null; status formal.
  - `prefillFromPending(p)`: database and sourceTag = the tag value, `imported: p.n`, date = the batch's local date,
    status formal.
- `foldPending(list, batch, now)` → list: a batch `{ tag, n, scopes: [scopeKey], at }` merges into a pending entry with
  the same tag and the same first scope seen within 30 minutes (n summed), else is added; at most 20 kept (oldest
  dropped). `dismissPending(list, id)`.

#### Zotero part

- `scopeOf(collection)`: the same keys as pico.js `scopeOf` (`<lib.path>/collections/<KEY>`, or `lib.path` for the
  library; name 「我的文獻庫」 for the user library).
- `dataDir()` = `PathUtils.join(Zotero.DataDirectory.dir, "zotero-bridge", "search-log")` (like fulltext.js cacheDir);
  `runtime.dataDir` overrides it in tests.
- `read(collection)` → `{ scope, entries, file, note: { path, rel, existing } | null }`: reads the JSON (missing = []),
  and when a vault is set reads the log note (path lookup like screening.reviewNotePath: `<name>.md`, then
  `<name> (<KEY>).md` when the first belongs to another collection by its `zotero_collection`), decodes its data block,
  and returns `mergeEntries(json, note)`.
- `write(collection, entries)`: writes the JSON (makeDirectory with createAncestors), then, when a vault is set, the
  note through `buildLogNote` (only when the text changed). Writes for one scope are serialized with a per-scope
  promise chain. A vault write error is logged and reported once; it never loses the JSON write.
- `append(collection, entry)`, `update(collection, id, fields)`, `remove(collection, id)` (tombstone), `promote(collection,
  id, status)`; each read → change → write, returns the entry.
- `autoDraft(collection, draft)`: no-op unless `featureOn("searchLog")` and `searchLog.autoDrafts`; uses `upsertAutoDraft`.
  Never throws (logs errors); callers don't await it in a way that can fail their run.
- `logDedupe(collection, info)`: no-op while the feature is off.
- `summaryFor(collection)` → `{ entries, formal, exploratory, dedupe, databases: databasesSearched(entries), link,

### 3.1 Pure: `searchHealth(input)` in screening.js

```js
searchHealth({
	prisma,          // computePrisma() result (E adds `untagged` to it: records with no 來源/ tag, both columns)
	cfg,             // screening config (otherSources, sourcePrefix)
	rows,            // the evidence rows of the included studies (evidenceRow output; `design` may be "")
	noData,          // included studies without an AI note (count)
	cardType,        // the collection's PICO card type ("meaning" = 質性) or ""
	chase,           // { note: bool }  a 「<collection> 引文追蹤」 note exists
	log,             // ZB.searchLog.summaryFor(collection) or null (feature off / not loaded)
	stopReason,      // the note's current search_stop_reason ("" when none)
}) → { flags: [{ code, text }], lines: [string], press: PRESS_ITEMS, stopReason, count: flags.length }
```

Rules — exactly the reviewer's six, written as these seven codes (1 and 2 are the one-database rule and its
「無法判斷」 variant), in this order; nothing else:

1. `unknownSources` — `prisma.untagged / total ≥ 0.2` (total = all records, both columns; at least 1 untagged):
   「無法判斷用了哪些資料庫：<n> 筆（<p>%）沒有「<prefix>」標籤。請先替匯入的文獻加上來源標籤（例如「<prefix>PubMed」「<prefix>華藝」），再重新產生。」
   When this fires, rule 2 is skipped.
2. `singleDatabase` — named databases = the `來源/` tag values in the database column (`prisma.sources`, without
   `未標示來源` and without catalog fallbacks — only real tags; E gets them from a new `prisma.tagSources` list of tag values
   it adds next to `untagged`) ∪ `log.databases` with method database; Google Scholar is not counted here. Exactly one:
   「目前只看到一個資料庫：<name>。方法章要怎麼說明只查一個資料庫？要不要再查 CINAHL、Cochrane 或華藝？」
3. `scholarAsDatabase` — a Google Scholar source (`sameSource` with "Google Scholar") in `prisma.sources` (database
   column): 「Google Scholar 算在「資料庫」欄（<n> 筆）。很多學校和期刊把它列為「其他方法」（補充檢索）；要不要改由你決定：在設定的「其他方法的來源」加上 Google Scholar，就會移到右欄。」 Only a flag: nothing is moved.
4. `includedOnlyScholar` — included records whose `來源/` tags are all Google Scholar:
   「有 <n> 篇納入研究只從 Google Scholar 找到：<up to 3 titles>。Google Scholar 的結果不容易重現，這幾篇在其他資料庫找得到嗎？」
5. `qualitativeNoCinahl` — `cardType === "meaning"` and no CINAHL among the tags (both columns) nor in `log.databases`:
   「這是質性（意義／經驗）問題，但來源和檢索日誌都沒有 CINAHL。護理的質性研究很多收在 CINAHL，要不要查一次？」
6. `rctsNoSR` — among `rows` with a non-empty `design`: RCT count ≥ 3 (`/\b(randomi[sz]ed|RCT)\b|隨機(分派|對照)/i` and
   not `/quasi|類實驗|非隨機/i`) and no SR or guideline (`/systematic review|meta-?analy|umbrella|guideline|系統性(文獻)?回顧|統合分析|後設分析|指引|指南/i`):
   「納入研究有 <n> 篇 RCT，但沒有系統性回顧或指引。依 6S 先往上層找：這個題目已經有人做過系統性回顧或指引嗎？」 + when `noData > 0`
   「（<noData> 篇納入研究沒有 AI 筆記，看不出研究設計，沒有算進去）」. When `noData > 0` and the rule does not fire, the
   same parenthesis is added as an extra `lines` entry so the card always says what was not counted.
7. `noCitationChasing` — `prisma.totalIncluded ≥ 1` and no `引文追蹤` source in `prisma.other` (or the database column),
   no `chase.note`, no log entry with method citation:
   「還沒有引文追蹤的紀錄（沒有「<prefix>引文追蹤」標籤、沒有引文追蹤筆記，檢索日誌也沒有）。可以用「引文追蹤：目前分類全文納入的研究」查參考文獻和被引用文獻。」

Dropped and never added:
CINAHL MH 未核對, 兩輪追蹤沒有新納入, 只有 MeSH 沒有自由詞.

`lines` also gets, in order: with `log === null` or `!log.hasLog`: 「還沒有檢索日誌：資料庫清單只看「<prefix>」標籤，查了 0 筆的資料庫不會出現。」;

`PRESS_ITEMS` (fixed, never generated per search), heading 「帶去給館員或指導教授看的 3 件事」:
1. 「檢索式：每個概念的同義詞、主題詞（MeSH／CINAHL Headings）和自由詞都有嗎？AND、OR、括號和截字用對了嗎？」

  MeSH Subheading 副標題; pt → Publication Type 文章類型; la → Language 語言; dp → Publication Date 出版日期; edat, crdt,
  mhda; sb → Subset; au, 1au, lastau, fau, ad, ta, jour, vi, ip, pg, pmid, pmc, aid, ot, nm, rn, gr, ps, pa, pl, si, cois,
  filter, jid, isbn, book, ed, ir, fir, cn, lid, tt, auid; and the long forms written out (Title/Abstract, MeSH Terms,
  MeSH Major Topic, All Fields, Text Word, Publication Type, Language, Title, Abstract, Author, Journal, MeSH Subheading).
  A proximity modifier `:~N` is accepted after tiab, ti, ad (and their long forms).
- `tokenize(q)` → `[{ type, text, start, end, field?, wildcard?, quoted? }]`, types `term`, `phrase`, `and`, `or`,
  `not` (operators in any case: `and` lower case is a word PubMed ignores — still type `and`, flag `lower: true`),
  `lparen`, `rparen`, `badquote` (an opening `"` without a closing one runs to the end and becomes this). A `[…]` right
  after a term or phrase is its `field` (raw, e.g. `mh:noexp`, `Title/Abstract`, `tiab:~3`). `*` inside a phrase sets
  `wildcard: true` on the phrase (supported by PubMed — never an error). `2015:2020[dp]` and `"2015"[dp] : "2020"[dp]` are
  date ranges: one term each side, the `:` is part of the range (no token of its own, no lint).
- `parse(q)` → `{ root, errors }`: groups by parentheses; each group lists its operands and the operators between them
  (adjacent operands = implicit AND, recorded as `{ op: "and", implicit: true }`). Unbalanced parentheses do not throw:
  `errors` gets `{ code: "unbalancedParens", open, close }`; an odd quote gets `{ code: "unbalancedQuotes" }`.
- `lint(q, { max = 3 } = {})` → `[{ code, text }]`, at most `max`, in this priority order (codes and texts exact):
  1. `unbalancedParens` 「括號沒有成對：左括號 <l> 個、右括號 <r> 個。PubMed 會丟掉多出來的括號，結果可能和你想的不一樣。」
  2. `unbalancedQuotes` 「引號沒有成對：PubMed 會忽略落單的引號。」
  3. `mixedAndOr` — one group (at any depth) has both AND (explicit or implicit) and OR among its own operators:
     「同一層同時有 AND 和 OR（<the group's text, ≤ 60 chars>）：PubMed 由左到右處理，不會先算 AND。同一個概念的同義詞可以用 OR 放進同一組括號。」
  4. `earlyNot` — a NOT that is not the last operator of its group, or a group that starts with NOT:
     「NOT 後面還有其他詞：PubMed 由左到右處理，NOT 之後的詞會接在排除之後計算。通常把 NOT 放在最後，並用括號包住前面整串。」
  5. `longNoParens` — no parentheses at all, no OR, and ≥ 5 bare terms (implicit or explicit AND):
     「<n> 個詞連成一串、沒有括號也沒有 OR：PubMed 會要求每個詞都出現。同義詞要用 OR 放在同一組括號裡。」
  6. `unknownField` 「PubMed 不認得欄位標籤 [<tag>]，會當成沒有欄位的詞（自動對應）。」 (first unknown tag only)
  7. `shortTruncation` — a term (not a phrase) ending in `*` whose root has fewer than 4 letters:
     「<term> 的字根少於 4 個字母，PubMed 不做截字，只找「<root>」。」
  Nested parentheses that are well formed never produce a note by themselves. `[mh:noexp]`, `[majr]`, `[tiab:~3]` on a
  phrase, a wildcard inside quotes and `[Title/Abstract]` are all valid and produce nothing.
- `explainTranslation({ query, translation, translationSet, lists, count })` → up to 6 lines (Chinese), from facts only:
  - each `translationSet` item whose `from` has no field tag and whose `to` has `"X"[MeSH Terms]`:
    「「<from>」→ 自動對到 MeSH「<X>」（也會找它底下的下位詞），原字也在所有欄位找」 (several MeSH joined with 、);
  - … with `[Subheading]`/`[MeSH Subheading]` only: 「「<from>」→ 對到副標題「<X>」」;
  - … with neither: 「「<from>」沒有對到 MeSH，只在所有欄位找這個字和字尾變化」;
  - a `from` with a tag (e.g. `Aged[majr]`): 「「<from>」：<FIELD_TAGS zh of the tag in `to`>」 (e.g. 主要主題; noexp →
    主題詞（不含下位詞）; Title/Abstract → 只在標題和摘要找，不會自動對到 MeSH);
  - user words (from `tokenize(query)` terms and phrase words, lower-cased, `*` and tags removed) that do not occur in
    `translation` (lower-cased): 「這些詞 PubMed 沒有用到：<words>」;
  - a user `*` term whose root shows in `translation` without `*`: 「<term> 沒有做截字（字根要 4 個字母以上）」;
  - `lists.phrasesIgnored`: 「被當成常用字略過：<…>（布林運算要寫成大寫 AND、OR、NOT）」 — the parenthesis only when one of
    them is `and`/`or`/`not`;
  - `lists.quotedPhrasesNotFound`: 「找不到完全相同的片語 <…>，PubMed 改用片語裡找得到的字分開找」;
  - `lists.phrasesNotFound`: 「PubMed 找不到、沒有用到：<…>」; `lists.fieldsNotFound`: 「PubMed 不認得的欄位：<…>」;
  - `lists.outputMessages`: `"("` or `")"` → 「有括號沒配對，PubMed 把它丟掉了」; /Unmatched double quote/ → 「有引號沒配對，PubMed 忽略了它」;
    /Wildcard search for '([^']+)' used only the first (\d+) variations/ → 「截字 <x> 只用了前 <n> 種字尾，把字根寫長一點」;
    `No items found.` → nothing (the count says it).
  - Lines are deduplicated and capped at 6 (mapping lines first). Empty translation → [].
- `countSentence(count, type)` → one neutral sentence, never a judgement or colour:
  - count 0: 「PubMed 找到 0 篇。先看上面有沒有被略過的詞或找不到的片語。」
  - otherwise 「PubMed 找到 <n> 篇。」 + by `type`: treatment 「治療／預防題做系統性回顧時，初步檢索常見幾百到幾千篇。」; diagnosis
    「診斷準確度的題目常比治療題少，幾十到幾百篇都常見。」; prognosis, etiology 「預後和病因題多是觀察性研究，幾百到上千篇都常見。」;
    meaning 「質性（經驗）題在 PubMed 常在 50 篇以下，也要查 CINAHL。」; other/empty 「筆數多少沒有標準答案。」 + always
    「可以拿 2–3 篇你知道一定要找到的文獻，看它們有沒有在結果裡。」 (`n` with thousands separators via `toLocaleString("en-US")`).
- `picoHints({ terms: [], mesh: [] }, { autoQuote = true } = {})` → up to 2 strings:
  - mesh present, no terms: 「有 MeSH 但沒有自由詞：剛收錄、還沒標上 MeSH 的新文獻會找不到，可以加幾個同義詞。」
  - terms present, none contains `*`, and some single-word term has ≥ 5 letters: 「可以考慮截字，例如 nurs* 同時找 nurse、nursing、nurses（字根至少 4 個字母）。」
  - with `autoQuote: false`, a multi-word term without quotes: 「多字的詞可以加引號當片語找，例如 "hand hygiene"。」
- `isUserQuery(query, generated)` → true unless `generated` (a string or an array) contains a string equal to `query`
  after NFKC, whitespace collapse, trim and lower case. Empty `generated` → true.
- `checkTest(detail, { generated, type, max = 3 })` → `{ user, notes, explain, count }`: when `!user` everything else is
  empty arrays/"" (F-wire shows only the one-line notice). Convenience for F-wire.
